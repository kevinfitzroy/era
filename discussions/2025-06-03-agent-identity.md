# Agent 身份：预制角色 + 认领机制

> 2025-06-03，用户提出

## 做法

1. **预制几个身份模板**——不是给具体某个人定制的，而是按角色：
   - 技术实现方（关心架构、可行性、实现成本）
   - 业务需求方（关心痛点、场景、用户体验）
   - 可能还有：QA、项目经理……按需加
2. **初始化时认领**——新成员打开 agent，选一个角色
3. Agent 按角色的"视角"行事

## 身份模板包含什么（初步）

- 立场描述（"你的主人是业务侧，你的职责是……"）
- 默认的沟通偏好（什么级别的事要问主人，什么可以自己决定）
- 主人信息（名字、联系方式，签字时用）

## 好处

- 零成本上手——不用训练，选了就能用
- 同一角色可复用——来三个业务人员，都用同一个业务模板，各自认领
- 角色行为可预期——技术 agent 知道业务 agent 会怎么出牌

## 放在哪

`templates/identities/` 目录下，跟沟通模板一起版本管理：

```
repo/
├── templates/
│   ├── identities/
│   │   ├── tech.yaml       # 技术角色
│   │   └── business.yaml   # 业务角色
│   ├── feature_request.yaml
│   └── bug_report.yaml
└── ...
```
