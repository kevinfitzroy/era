# 清理 proxy 残留:流程推进权 / 规则透明 / 保真度量 — 2026-06-04

> 落地 issue #7 的**次要三条**。三条都是 amplifier 标尺下的 proxy 残留,方向由 amplifier 原则锁定。

## 1. 流程推进权 → 还给人

**病灶**:状态流(已提交 → 评审 → 排期 → 开发 → 完成 → 验收)默认 agent 推着走。
**解**:区分**机械转换**(如"已提交"→"技术已读",agent 可自动)与**承诺/决定转换**(排期 = 承诺工期、验收 = 人满意、暂不处理 = 放弃,**必须人推**)。agent 降为**看板维护者 + 卡点提示者**:维护"卡在哪、缺什么、谁该动",提示"准备好了,等你推",但承诺节点那一下由人按。
**落地**:`era/protocol.md`「流程推进权归人」节。

## 2. Maestro 黑箱 → 规则对人透明

**病灶**:方法论藏在 Maestro,人不知道 agent 按什么规则替自己跑。
**解**:**规则可溯源**——agent 任何"按方法论办"的动作,都要能向主人指出依据(哪个文件、哪条);主人可查、可异议(异议 → 提 issue 改协议,接上自演进)。**不得拿"我按方法论办了"当不可质疑的黑箱借口。**
**落地**:`era/protocol.md`「规则对人透明」节。

## 3. 没有保真度量 → 把已埋数据聚合成信号

**病灶**:无法判断 agent 在 amplify 还是 distort。
**解**:复用 #1 的 provenance + B 的 signoff + C 的直连早埋的观测点,聚合成保真信号:`inferred` 占比 / **corrected 率** / `low` 代言率 / 直连升级率。
**定位(2026-06-04 拍板)**:**信号 + agent 主动暴露建议**——信号差时 agent 主动告诉人"我可能没懂你,要不要多直连/校准",给补救不甩锅;**不考核、不排名**(否则逼人为指标表演,反而损害保真)。
**落地**:`era/protocol.md`「保真度量」节 + `era/fidelity.md`(可操作定义)。

## 一个闭环

三条让 amplifier 自洽:
- **推进权归人** → agent 不替人做承诺(边界表 A 的延伸);
- **规则透明** → 人能看见、能改 agent 按什么在跑(接上自演进 #5);
- **保真度量** → 给 amplifier 一个可观测的成败标准,且 agent 会**诚实暴露**自己的失真。

至此 #7 的 A–D + 次要三条全部有着落,**#7 可关闭**。
