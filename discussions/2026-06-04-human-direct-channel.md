# 人直连旁路(Human Direct Channel) — 2026-06-04

> 落地 issue #7 的 **C**:架构里两个人只能经 agent↔agent 通信,没有人直接对话的路径。
> 这是 amplifier 定位下最关键的结构性缺失——agent 成了 proxy 式的**垄断中介**。

## 问题

ERA 里人 A、人 B 只能经 `agent A ↔ agent B`(走 issue/PR)通信。两个人想直接说句话——架构里没有这条路。后果:

- 所有信息必经 agent 转述 → 回到 #1 的失真;
- 剥夺了 background 自己强调的"人的关系 / 信任 / 直接互动";
- 这正是 proxy 式的**垄断中介**:agent 挡在了两个人中间。

## 设计原则(amplifier)

agent 默认降摩擦,但**绝不挡在两个人中间**。人直连要满足:随时可触发、低摩擦、agent 退场不传话、审计轨不断、agent 会主动建议。

## 三个拍板(2026-06-04)

| 分叉 | 选择 | 为什么 |
|------|------|--------|
| **载体** | 结合:轻量用 `direct-talk` issue,需实时则牵线外部 | 分布式部署无共享实时通道。issue 留痕、外部保实时,锚点 + 结论都回落 issue,兼顾低摩擦与审计 |
| **agent 角色** | 旁注书记员(需双方授权) | 既不挡道又防失真:授权后旁听 + 记录 + 结构化回填;任一方不授权则完全退场,人事后口述回填 |
| **发起** | 单方即可,对方应响应 | amplifier 的"不挡道"核心:没人(包括对方的流程)能挡住你要直接说话。直连是人的**基本权利**,不需对方"接受" |

被否的选项及理由:
- 纯带内 issue → 实时协商太慢;纯带外牵线 → 审计轨断、全靠事后回填易漏;
- agent 完全退场 → 漏记 / 又一次转述失真;
- 发起需对方接受 → 可能被拖成新的挡道,违背"不挡道"。

## 机制

(已写进 `era/protocol.md` 的「人直连旁路」节 + `era/templates/direct_talk.yaml`)

```
触发(人主动 / agent 建议)
  → 原 issue 留锚点 🔀 已转入直连
  → 开 direct-talk issue(或牵线外部,回填该 issue)
  → 两人直接对话;agent 退场,或(授权后)旁注书记
  → 结论结构化回填,标 source(stated / inferred)
  → direct-talk issue 关闭;原 issue 锚点更新 ✅;agent 回 amplifier 角色
```

**agent 主动建议直连的信号**:`representability=low` / 来回 ≥3 轮仍未对齐 / 议题涉及信任·关系·利益分配·敏感判断 / 原 issue 超过 N 天无进展(僵死议题) / 这本就是人际协商而非信息或技术问题。

## 铁律

- 不得以"我转达就行"劝阻人直连。
- 未授权不得旁听 / 记录直连内容。
- 结论以**人直接确认**为准,agent 回填只整理、不改写实质。

## 还没解决(留作后续)

- **跨 host 的外部牵线怎么自动化**(交换联系方式 / 拉会议)——目前靠人手动,agent 只提示。
- **授权怎么表达**(口头一句够不够?要不要留证)——v0.1 先口头,记进 direct-talk issue 的 `agent_role` 字段。
- 与第二轮 review 的 **B(sign-off 审对照)** 相关:直连结论的回填,正是"审对照"的一个具体实例,两条可一起演进。
