# 场景拆解：报 Bug

> 2025-06-03，草稿 v0.1，与提需求结构对齐

## 流程（5 步）

### 第 1 步：捕捉

Agent 引导人描述问题表象：

```
Agent: "出了什么问题？你看到了什么现象？"
Agent: "本来应该是什么样？"
Agent: "这个问题是怎么触发的？能复现吗？"
Agent: "影响有多大？一个人遇到还是都遇到了？"
```

### 第 2 步：结构化

```yaml
type: bug_report
id: BUG-20250603-001
title: "月度汇总报表查询超时"
symptom: "打开报表后页面一直转圈，最终显示加载失败"
expected: "3 秒内显示报表数据"
steps_to_reproduce:
  - "进入财务模块"
  - "点击月度汇总报表"
  - "等待 > 10 秒后报错"
environment: "Chrome 浏览器，公司内网"
severity: "high"              # 业务 Agent 初步判断
affected_users: "财务团队全员"
unknowns:
  - "是否特定时间段出现？"
  - "浏览器控制台有无报错信息？"
```

### 第 3 步：确认

Agent 回放给人，"你看我理解得对不对？"

### 第 4 步：Agent ↔ Agent

业务 Agent → 技术 Agent：用 `templates/bug_report.yaml` 开 Issue。

### 第 5 步：跟踪

```
已报告 → 确认中 → 修复中 → 已修复 → 已验证
              ↓
           需更多信息（回到第 1 步）
```

## 和提需求的区别

| | 提需求 | 报 Bug |
|--|--------|--------|
| 核心问题 | "我想要什么" | "什么坏了" |
| Agent 侧重追问 | 痛点、期望、场景 | 复现步骤、环境、影响范围 |
| 技术侧响应 | 评估可行性 + 排期 | 确认 bug + 修复方案 |
