# 项目背景与核心命题 — 2025-06-03

## 要解决什么

构建一套**团队内部协作的沟通框架**，核心假设：**每个成员都由 AI agent 替自己发声**，整个工作流程由 agent 把控。

## 领域范围

- **纯软件工程**：不涉及硬件、不需要人亲自物理操作
- 大部分任务是两类：
  - **信息流处理**（需求传递、方案讨论、进度同步、决策记录）
  - **工具制作**（写代码、搭系统、做内部工具）
- 产物都是数字化的（代码、文档、设计），agent 可以直接参与生产和协商

## 关键约束

- **不是面向普通用户的产品**，是团队内部用的系统
- **团队规模大**，但**负责构建这个框架的人很少**（目前 2 人）
- 角色分工：
  - 用户：软件工程 + AI 背景
  - 另一位：懂业务，无技术背景
- **基础要求**：人人都让 AI agent 来替自己发声，agent 驱动流程

## 核心模式（第二轮细化）

## ERA 全称

**E**ntity **R**epresentative **A**gent —— 每个人的"实体代表 agent"

---

## 核心模式

```
人 A ←→ Agent A  ────异步协商────  Agent B ←→ 人 B
                       │
                  Agent 之间来回沟通、
                  谈判、协调
                       │
                       ↓
                  达成方案 → 各自人类 sign-off
```

- 类比：像异步论坛/IM，但**来回发消息的是 agent**，不是人
- 人类只做 **sign-off**（审批/确认），不参与中间的消息往返
- 人类可以随时查看完整对话记录（"会议纪要"），透明可追溯

### 关键洞察

- **不是去人化**：人的关系、信任、判断仍然重要
- 人跟人之间仍然有直接互动，但日常协调的"消息往返"由 agent 代劳
- Agent 是人的**代言人/代表**，不是替代品

## ERA 的两大支柱（并重）

| 支柱 | 核心问题 |
|------|----------|
| **Agent ↔ Agent** | Agent 之间怎么协商、传递信息、达成方案 |
| **Human ↔ Agent** | Agent 怎么引导人把事说清楚、怎么帮人完善想法 |

## 第四轮细化：方法论的核心——内容与流程

输入方式（打字/语音）不是重点。重点是 **内容和流程**。

### 方法论要回答的具体问题

- **Feature 怎么提**：从"我有个想法"到"这个需求可以进开发了"，中间走几步？
- **Bug 怎么反馈**：业务侧看到问题，怎么结构化地报给技术侧？
- **功能定义分几步**：一个想法从不成熟到成熟，需要经过哪些阶段？

### 核心目标：消除"上手懵"

```
新人/非技术者的状态：          方法论引导后：
"不知道要干什么"      →      "知道一步一步怎么走"
```

方法论的价值 = **降低认知门槛**。人不应该需要先"学会怎么沟通"才能参与协作。ERA 替他把路铺好。

### 这意味着 ERA 包含两层

| 层 | 内容 |
|----|------|
| **流程层** | 每种协作动作（提需求、报 bug、方案评审…）的标准步骤 |
| **Agent 层** | Agent 在每个步骤里做什么——什么时候追问、什么时候格式化、什么时候升级给人 |

两个非技术背景的人来了，打开 agent，agent 引导他："你是想提一个功能需求，还是反馈一个问题？来，一步一步说。"

### 技术侧 Agent（用户自己的）

- 偏**系统/架构/实现**视角
- 理解代码约束、技术债务、可行性边界
- 把宏观需求翻译成技术方案

### 业务侧 Agent（搭档的）

- 偏**问题描述/表象捕捉/反馈**视角
- 把人的直接感受、模糊印象 → **格式化文档**
- **主动提问完善想法**，不依赖人的表达素养
- 不让人受制于"有的人能说清楚、有的人说不清楚"

### Agent 作为"沟通均衡器"

核心观点：**AI agent 应该帮助人完善信息，而不是被动转录**。

```
人以为自己表达了 100%
        ↓
实际只说出了 50-60%（信息天然衰减）
        ↓
对方只接收到 50%（再一次衰减）
        ↓
＝ 误解、冲突的根源
```

Agent 的职责：**在发送端补齐缺口、在接收端追问澄清**，把两边的衰减都堵住。

## 自演进协议（Self-Evolving Protocol）

沟通约定**不能一开始就定死**：

- 在实践中迭代升级（用户主导）
- 升级后，**所有参与方的 agent 自动同步最新版本**
- 所有 agent 始终按最新规范沟通
- 这本身就是一个"活文档"问题——谁维护、怎么分发、怎么确保 agent 真的遵守了新规范

## 核心张力（持续更新）

1. Agent 替人发声的边界——什么它可以自己决定，什么必须等人拍板？
2. 非对称 agent 之间用什么"通用语言"沟通？结构化文档？自然语言？混合？
3. 非技术背景的人怎么"训练"自己的 agent？他需要能跟自己的 agent 对话吗？
4. ERA 协议本身是什么形态？版本化规范文件？Agent 怎么自动发现并加载新版本？
5. Sign-off 机制怎么设计？Agent 达成的方案，人怎么快速理解并批准？
6. 两个 agent 谈不拢时的升级路径？
7. **自演进**：谁来改协议？改完怎么审？怎么确保所有 agent 同步？
