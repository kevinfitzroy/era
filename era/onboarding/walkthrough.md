# 上手走一遍:ERA 怎么跟你打交道

> 这页是给**人**看的(不是给 agent)。你刚拿到自己的 agent,这 5 分钟让你明白怎么用它。
> 一句话:**你说人话,agent 帮你把话说清、替你走流程;你只做两件事——确认理解、拍板分歧。**
>
> (你的 agent 第一次上线、认领完身份后,会主动用这页带你走一遍。你也可以随时自己回来读。)

## 最重要的三件事

1. **直接说大白话**。别管格式、别想"该填哪个字段"。你说"报表太慢了我受不了",剩下的交给 agent。
2. **它会挑重点跟你核对**(不是整段念给你点头)。它只把**替你补的 / 没跟你确认的 / 改了你原意的**地方拎出来让你拍,其余默认采纳。所以你确认起来很快。
3. **你随时能甩开 agent**。想直接找对方的人谈?说一声,agent 立刻让路(人直连)。**决定权永远在你**,agent 只是放大你的声音,不替你做主。

## 你能让它干什么——四类常见 + 一类"全新的事"

### ① 提个需求("我想要……更好")
> **你**:"月底那个汇总报表慢得要命,大家都在等。"
> **agent**:帮你理清痛点 / 期望 / 影响范围 → 写成一个**需求 Issue**;把"我猜你想要 3 秒内打开(你没明说)"这条**单独拎出来**让你确认。
> **你**:"5 秒就行。" → 定稿。对接角色(技术侧)的 agent 会接到。

### ② 报个 Bug("这东西坏了")
> **你**:"报表点开一直转圈,最后报错。"
> **agent**:追问复现步骤、什么环境 → 写成 **Bug Issue**。
> 你要是说这是要命的故障(critical / high),**它会让你确认一遍才发**——不拿没核实的高危描述把技术侧支使得团团转。

### ③ 起一个编码任务("把这个做出来")
> **你**:"那报表加速,就这么定了,做吧。"
> **技术侧 agent**:出方案(怎么做、要多久、取舍、风险)→ 提 **PR**;其它角色的 agent 按各自视角评审,还会专门跑一遍**红队视角**(故意找这方案会怎么崩)。
> 意见分歧大,**不会和稀泥凑一致**——摊给你拍板。

### ④ 内部协作("跟别人对一下")
> 跨角色的事(业务 ↔ 技术)默认走 Issue / PR,各自的 agent 代言各自的人。
> 一旦涉及**信任、利益分配、或反复对不齐**,agent 会主动提:"要不要你俩直接谈?" 然后让路——只在你们都授权时旁边记个要点。

### ⑤ 想干一件全新的、不属于上面任何一类的事
> 直接说就行。agent 帮你判断这到底是**需求 / bug / 得先讨论 / 还是该两个人直接谈**,带你走对应的路。
> 如果你觉得是 **ERA 这套方法本身**哪里不对劲——那叫"挑战方法论",agent 帮你记进 `challenges/`(一份永不关闭的已知弱点清单)。

## 你看到的每条信息,都标了出处

agent 写的东西会标:`stated`(你亲口说的)/ `inferred`(它替你补的)/ `unconfirmed`(还没跟你确认的)。
**这是为了让你一眼看出哪句是你的本意、哪句是它的猜测。** 它拿不准能不能准确代表你时,会直说"这个我代表不了",把你拉进来——它是**放大器,不是替你拍板的代理人**。

## 规则都在你手边

你和 agent 遵循的规则全在 `era/` 下(协议 `protocol.md`、你的角色 `identities/`、各种格式 `templates/`)。
**你随时能让 agent 把依据调出来给你看、能让它改**(改就提个 issue / PR)。不存在"我按方法论办了"的黑箱借口。
