# 保真度量(Fidelity):你在 amplify 还是 distort?

> amplifier 的成败标准:agent 的产出有多忠实于人的原意。
> proxy 不在乎(反正替你做了);amplifier 必须**可观测**。
> 定位(2026-06-04 拍板):**信号 + agent 主动暴露建议**,不考核、不排名。
> 设计背景见 `../discussions/2026-06-04-proxy-residue-cleanup.md`。

## 四个指标(都来自已有数据,不用造新埋点)

| 指标 | 怎么算 | 信号含义 |
|------|--------|---------|
| **inferred 占比** | 一次产出里 `source: inferred` 的字段 / 总字段 | 你替人"造"的比例;越高越像在替人写而非帮人写 |
| **corrected 率** | sign-off 里 `verdict: corrected` 的点 / 需人拍的点 | **最直接的失真信号**:人把你的理解改了多少 |
| **low 代言率** | `representability: low` 次数 / 总次数 | 你多频繁地"代表不了" |
| **直连升级率** | 转入人直连的议题 / 总议题 | 代言失败、需人亲自上的频率 |

数据来源:`feature_request` / `bug_report` 的 `source` + `signoff` + `representability` 字段、`direct_talk` issue。聚合粒度可按「人 × 周」或「每个议题」。

## 你(agent)怎么用:信号 + 主动暴露

1. **自评,不打扰**:常态下默默算,不每次汇报。
2. **信号差时主动暴露**:某指标明显偏高(如 corrected 率 > ~1/3),主动跟主人说——
   > "最近我大概有三成的理解被你改掉,可能没太对上你的频道——要不要这周多直连几次,或者花十分钟帮我校准一下?"
3. **给补救,不甩锅**:暴露的同时给具体建议(多直连 / 校准身份文件 / 放慢 sign-off 颗粒度),而不是"我尽力了"。
4. **不考核、不排名**:这些数**不**拿去跨人 / 跨 agent 比高低——那会逼人为指标表演(少标 inferred、少请 corrected),反而损害真实保真。

## 保真是双向的:别只盯"改得多"

corrected 率高 = agent 失真;但 **corrected 率长期为 0 同样可疑**——很可能不是 agent 准,而是人在**惯性点头**(假精准)。一个从不被改的 agent,不是完美,是没人真在审。

- corrected 率**偏高** → agent 没懂人(distort);
- corrected 率**长期为 0** → sign-off 可能流于形式(B 的差异驱动正为治这个);此时你该反过来提醒人:"你最近从没改过我——是真对上了,还是没细看?"

失真和假精准一样值得警惕。保真信号是**双向**的。

## 阈值是软的

上面的 ~1/3 只是起点,不是硬线。真实阈值在使用中校准——这本身又是一次自演进:发现阈值不对 → 提 issue 改本文件。重点是**让失真可见、可补救**,不是卡一个精确数字。
